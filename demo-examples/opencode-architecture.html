PRIMITIVE 01

Context window

Turn assembly is staged: load history, filter compacted ranges, project to the AI SDK ModelMessage shape, prepend a composed system block, then hand the array to streamText. Reminders are injected synthetically into the last user message; overflow triggers automatic compaction.

turn-state compaction system-prompt
  • packages/opencode/src/session/prompt.ts : 1256–1258

    History is loaded, MessageV2.filterCompactedEffect() drops compacted turns, then MessageV2.latest() picks the most recent user/assistant pair plus pending subtask parts.

  • packages/opencode/src/session/prompt.ts : 1435–1441

    System prompt assembly: provider-specific prompt + environment info + instruction files (AGENTS.md/CLAUDE.md) are collected in parallel and joined.

  • packages/opencode/src/session/prompt.ts : 1444–1455

    Final dispatch hands system block, converted messages, tools dict, and a MAX_STEPS suffix to handle.process() for streaming.

  • packages/opencode/src/session/message-v2.ts : 630–739

    toModelMessagesEffect() projects internal MessageV2 parts (text, file, tool_call, reasoning, attachment) to the AI SDK ModelMessage shape.

  • packages/opencode/src/session/reminders.ts : 14–80

    System reminders (plan-mode entry/exit, agent switches) are appended as synthetic text parts on the last user message, not as separate system entries.

  • packages/opencode/src/session/llm/request.ts : 54–103

    System array is composed from agent prompt + env + instructions + user override. For OAuth/workflow models, system content is hoisted into options.instructions rather than a system-role message.

  • packages/opencode/src/session/overflow.ts : 20–32

    isOverflow() compares total tokens to usable context (model limit minus reserved buffer). If the budget is exceeded and auto-compaction is on, compaction fires.

  • packages/opencode/src/session/compaction.ts : 245–277

    select() keeps the last N recent turns (default 2) under a token budget and stamps a tail_start_id as the cut point; older turns are dropped and summarised.

  • packages/opencode/src/session/message-v2.ts : 1014–1064

    filterCompacted() reorders the post-compaction stream so the summary assistant message precedes the retained tail — the LLM sees a chronologically clean history.

  • packages/opencode/src/session/system.ts : 65–77

    Available skills are listed in the system prompt as a <available_skills> XML block, filtered by agent permissions via Skill.available(agent).

PRIMITIVE 02

Tools

Each tool is an Effect.Schema-typed Def with an execute function. The registry lazily wires builtin + plugin + MCP tools and feature-gates them per model. SessionTools.resolve() wraps each tool for the AI SDK with permission checks and lifecycle hooks.

effect-schema ai-sdk lazy-registry

    The Def interface — every tool exports { id, description, parameters, jsonSchema, execute }; execute returns an ExecuteResult.

  • packages/opencode/src/tool/tool.ts : 34–44

    The execution Context carries session/message IDs, an abort signal, a permission asker, message history, and a metadata-update callback.

  • packages/opencode/src/tool/tool.ts : 149–167

    define() factory typed-validates parameters with Effect Schema and applies per-agent output truncation around execute.

  • packages/opencode/src/tool/registry.ts : 107–270

    The registry layer lazily initialises builtin + plugin tools and feature-gates (WebSearch, LSP, apply_patch vs edit) based on model/flags.

  • packages/opencode/src/tool/registry.ts : 141–197

    Plugin tools are bridged in: Zod schemas are translated to JSON Schema and the plugin's execute is wrapped to normalise promises and truncate output.

  • packages/opencode/src/tool/registry.ts : 316–361

    tools() filters the active set per model capability and fires tool.definition plugin hooks for schema customisation before returning.

  • packages/opencode/src/session/tools.ts : 24–115

    SessionTools.resolve() turns registry defs into AI SDK tool() objects with permission asks, plugin before/after hooks, and artifact handling.

  • packages/opencode/src/session/llm.ts : 272–304

    streamText() from the AI SDK receives the prepared tools dict and dispatches calls — the processor consumes the resulting tool-call/tool-result events.

  • packages/opencode/src/tool/read.ts : 29–37

  • packages/opencode/src/tool/edit.ts : 58–70

  • packages/opencode/src/tool/grep.ts : 32–54

    Example tool — Grep demonstrates ctx.ask() for permission, ctx.abort for cancellation, and a metadata truncated flag.

  • packages/opencode/src/tool/invalid.ts : 9–20

    Fallback invalid tool — when the model emits malformed tool args, execute_repair in llm.ts:278 redirects to it with the parse error.

PRIMITIVE 03

Permissions & sandbox

A last-match-wins rule engine over typed actions (allow / ask / deny) drives every tool call. Bash commands are parsed and matched by command-prefix arity. There is no OS-level sandbox — opencode relies on path-containment checks and user prompting; security isolation is the user's responsibility (Docker/VM).

allow/ask/deny arity-aware bash no OS sandbox
A · Permission model (allow / ask / deny)
  • packages/core/src/permission.ts : 21–31

    evaluate() walks ruleset arrays last-match-wins with wildcard pattern matching; the default verdict when nothing matches is ask.

  • packages/opencode/src/permission/index.ts : 138–140

    Re-exports the core evaluator and threads the allow → continue, deny → DeniedError, ask → prompt flow into tool execution.

  • packages/opencode/src/permission/index.ts : 171–211

    ask() queues a pending request, fires a bus event, and suspends the tool effect until reply() resolves it.

  • packages/opencode/src/permission/index.ts : 213–269

    reply() handles user verdicts — "reject" fails all pending requests in the session, "once" proceeds, "always" persists a new approve rule and unblocks any matching pending requests.

  • packages/opencode/src/config/permission.ts : 1–58

    Config schema — nine permission types (read, edit, bash, grep, task, external_directory, webfetch, websearch, skill) × three actions, with per-target pattern matching.

  • packages/opencode/src/permission/arity.ts : 1–163

    Arity table mapping command prefixes (e.g. npm run → 3) to token counts; used to extract a human-readable, matchable command shape from a shell line.

  • packages/opencode/src/tool/shell.ts : 260–410

    collect() parses bash/PowerShell AST, extracts referenced file paths, runs path-containment checks, and builds the permission request using the arity-aware prefix.

  • packages/opencode/src/agent/subagent-permissions.ts : 17–34

    Subagents inherit parent edit denies (Plan Mode), parent session deny rules, and default to denying task/todowrite unless explicitly granted.

B · Sandbox mechanism (path containment only)
Honest disclosure. SECURITY.md states plainly: "opencode does not sandbox the agent. The permission system exists as a UX feature… it is not designed to provide security isolation." True isolation requires Docker or a VM.
  • SECURITY.md : 15–19

    Explicit statement that the agent is unsandboxed; permissions are a UX guardrail, not a security boundary.

  • packages/opencode/src/project/instance-context.ts : 18–24

    containsPath() tests whether a path falls inside the project or an attached worktree; drives the external_directory permission prompt.

  • packages/opencode/src/tool/external-directory.ts : 16–45

    Validates file paths before file operations; if the target lies outside the project, requests external_directory permission with the parent dir as the glob target.

  • packages/opencode/src/tool/shell.ts : 289–306

    Shell execution uses Effect's ChildProcess.make() with shell: true — standard Node spawning, no seatbelt, bubblewrap, or restricted tokens.

  • packages/opencode/src/tool/shell.ts : 424–596

    run() handles stdout/stderr capture, timeout, and abort, but applies no syscall filtering or capability dropping.

PRIMITIVE 04

Skills

Skills are SKILL.md files (YAML frontmatter + body) discovered from ~/.claude, ~/.agents, project config dirs, and remote URLs. They're listed by name/description in the system prompt and loaded on demand by a dedicated Skill tool.

SKILL.md frontmatter lazy-load

  • packages/opencode/src/skill/index.ts : 52–58

  • packages/opencode/src/skill/index.ts : 104–141

  • packages/opencode/src/skill/index.ts : 173–233

  • packages/opencode/src/skill/discovery.ts : 54–104

    Discovery.pull() downloads a remote index.json manifest, fetches each listed skill's files into a cache dir, and confirms SKILL.md is present.

  • packages/opencode/src/skill/index.ts : 274–279

  • packages/opencode/src/tool/skill.ts : 14–72

PRIMITIVE 05

Plugins

A plugin is an async function exporting a Hooks object. The PluginLoader resolves npm or file:// specs, dynamically imports them, and calls them with a PluginInput bundle (SDK client, project context, Bun shell). Hooks span events, config, tool definitions, auth, provider, chat lifecycle, shell env, and tool execute before/after.

async-fn npm + file:// 18+ hooks

    Public SDK — defines Plugin (async fn → Hooks) and PluginModule shape (id, server, optional tui).

  • packages/plugin/src/index.ts : 56–66

    PluginInput bundles the SDK client, project context, directory/worktree paths, a workspace-adapter register, and an optional Bun $ shell.

  • packages/plugin/src/index.ts : 222–333

    The Hooks interface — event, config, tool, auth, provider, chat.message, chat.params, permission.ask, shell.env, tool.execute.before/after, plus experimental compaction/system hooks.

  • packages/opencode/src/plugin/loader.ts : 75–236

    PluginLoader normalises specs into plans, resolves npm or file targets, detects the entrypoint, validates engine compatibility, and dynamic-imports with retry.

  • packages/opencode/src/plugin/index.ts : 99–109

  • packages/opencode/src/plugin/index.ts : 61–71

PRIMITIVE 06

MCP

Two server types — Local (stdio process) and Remote (HTTP). For remote, opencode tries StreamableHTTPClientTransport first and falls back to SSE. Tool names are prefixed clientName_toolName; prompts surface as dynamic slash-commands, resources as HTTP API endpoints. OAuth with dynamic client registration is supported end-to-end.

PRIMITIVE 07

Memory (AGENTS.md)

Opencode's always-loaded instruction file is AGENTS.md, with CLAUDE.md and (deprecated) CONTEXT.md as accepted fallbacks. Discovery walks up from the current dir, plus a global override at ~/.opencode/AGENTS.md. Each file is prepended with an "Instructions from: <path>" header before being joined into the system prompt.

PRIMITIVE 08

Subagents

The task tool spawns a fresh Session with a parentID pointer and a derived permission set. Three native roles ship in-tree — general, explore, scout — each with its own system prompt file. Foreground subagents return the final assistant text; an experimental background mode returns immediately and notifies on completion.

    Three native subagent roles — general (multistep work), explore (codebase search specialist), scout (read-only docs/dep research).

  • packages/opencode/src/session/session.ts : 657–676

  • packages/opencode/src/session/llm/request.ts : 54–64

+ ADDITIONAL

Distinctive primitives

Beyond the named eight, opencode treats several pieces as first-class runtime concerns. These didn't fit cleanly into the canonical taxonomy but matter a lot in practice for understanding how the runtime behaves.

bus processor snapshot worktree lsp acp
  • packages/opencode/src/session/processor.ts : 30–100

    Session processor — the agent loop. Drives the main turn execution, consumes streamed LLM responses, and provides handles to update tool calls mid-stream. Tracks toolcalls, snapshot, compaction state, and reasoning map per turn.

  • packages/opencode/src/bus/index.ts : 1–100

    Typed event bus. Central pub/sub with Schema-validated event definitions; supports both eager subscriptions (acquired at yield* time to avoid race windows) and callback listeners.

  • packages/opencode/src/snapshot/index.ts : 1–100

    Auto-snapshot per session. Each session has an isolated git repo (hash-keyed) capturing filesystem state at each turn; session/revert.ts:1–80 exposes revert-to-point with selective patch application.

  • packages/opencode/src/worktree/index.ts : 1–80

    Per-session git worktrees. Creates isolated worktrees with optional startup commands, emits worktree.ready/worktree.failed, and supports reset/removal — the primitive enabling parallel session isolation.

  • packages/opencode/src/question/index.ts : 1–100

    Interactive question service. Agents can ask multi-choice or free-form questions mid-turn; publishes Asked/Replied/Rejected bus events. Rejection blocks execution with QuestionRejectedError.

  • packages/opencode/src/session/run-state.ts : 1–80

    Run-state & doom-loop guard. Enforces a single concurrent execution per session via a Runner abstraction with cancellation, interrupt handlers, and a three-attempt threshold to break runaway loops.

  • packages/opencode/src/lsp/lsp.ts

    LSP integration. Manages language servers per project and exposes a tool for the LLM to query symbols, diagnostics, and references in real time — direct compiler-grade signal instead of pure text scraping.

  • packages/opencode/src/acp-next/service.ts

    ACP (Agent Coding Protocol). Agent-side protocol for session negotiation, model switching, and config options — what external IDE/host integrations talk to.

  • packages/opencode/src/session/reminders.ts

    Plan mode + reminders. Bridges plan-mode → build-mode transitions and emits synthetic reminders into the conversation when the agent or mode changes mid-session.

  • packages/opencode/src/session/todo.ts

    Session-scoped TODO state. First-class task tracking surfaced through the todowrite tool; persisted with the session so progress survives compaction.
